# 03 · 本地打包与服务器部署（Docker 离线）

> 面向「本机有 Docker Desktop，打完包上传到阿里云服务器」这条路线。
> 本文只讲**打包与部署**，不涉及数据源改造（那是挂起项，另行处理）。
> 本工具仅用于行情数据的研究性查看与可视化，不构成任何投资建议。

---

## 一、总览：打包什么、部署什么

```
   本机 Windows（Docker Desktop）                    阿里云 ECS（Ubuntu）
  ┌───────────────────────────┐                 ┌────────────────────────────────┐
  │ ① npm run build           │   dist/         │  bash deploy.sh                │
  │ ② docker build（后端镜像）│                 │   ├ docker load kanban-images  │
  │ ③ docker save（后端+nginx）│ ──────────────▶ │   └ docker compose up -d       │
  │ ④ 组装 kanban-deploy-*    │    scp/上传     │      ┌─ web(nginx) :80 ────────┐│
  │    data/ + config/        │                 │      │  /        → dist/       ││
  └───────────────────────────┘                 │      │  /api/    → app:8000    ││
                                                │      │  auth_basic 全站口令    ││
                                                │      └─────────────────────────┘│
                                                │      └─ app(uvicorn) 不对公网开 │
                                                │         ├ 卷挂 data/  (SQLite)  │
                                                │         └ 卷挂 config/ (评分)   │
                                                └────────────────────────────────┘
```

**三条设计取舍（理解了这三条，后面都是细节）：**

1. **镜像只装后端**。前端 `dist/` 作为部署包里的普通目录挂给 nginx —— 前端改版只要重新 `npm run build` 覆盖目录、`restart web`，不用碰镜像，也省掉 node 构建阶段。
2. **`data/` 与 `config/` 不进镜像**。`market.db` 里存着飞书 `app_id`/`app_secret`/`owner`，进镜像就等于把凭据打进一个会被到处传的文件；不进镜像，升级镜像也不会丢关注列表、任务开关和历史数据。
3. **两个镜像一起 save**。服务器直接 `docker load`，**不需要在服务器上配 Docker Hub 加速源**（国内服务器拉 docker.io 是笔糊涂账，离线带上最省事）。

## 二、打包产物长什么样

```
kanban-deploy-20260929/
├── kanban-images-1.0.tar    # 后端镜像 + nginx:1.27-alpine（离线包，约 0.7~1 GB）
├── docker-compose.yml       # 从 deploy/ 复制
├── deploy.sh                # 服务器端一键：load + up + 自检
├── probe.sh                 # 出站连通性预检（东财/腾讯/飞书，只读）
├── backup.sh                # SQLite 一致性快照 + 留 14 份 + crontab 用法
├── dist/                    # 前端产物（npm run build，4 个文件约 1.7 MB）
│   ├── index.html
│   └── assets/
├── data/                    # ← 数据迁移就这一个目录
│   ├── market.db            # 1.55 MB：看板数据 + 关注 + 任务开关 + 飞书凭据
│   └── trade_calendar.json  # 103 KB：交易日历缓存（路径写死在 DATA_DIR，必须跟着走）
├── config/
│   └── scorer.yaml          # 5.4 KB：主力建仓评分模型，服务器上改完 restart 即生效
└── nginx/
    ├── default.conf         # 静态 + /api 反代 + 全站 basic_auth
    └── .htpasswd             # 口令文件（生成方式见第三节末）
```

> ⚠️ 这个目录**含飞书 app_secret**，等同于你飞书机器人的密码。
> 不要提交进 git、不要发给别人、不要截图外传。真担心的话，打包前去飞书后台重置一次 Secret，再在看板页面重新填。

## 三、本地打包（PowerShell，可整块复制）

**前提：Docker Desktop 已启动**（托盘鲸鱼图标在跑，`docker version` 能返回 Server 版本）。

```powershell
cd D:\test-kanban

# 1) 前端产物：tsc -b && vite build
cd frontend
npm ci                 # 依赖没变可跳过
npm run build
cd ..

# 2) 构建后端镜像。构建上下文=仓库根，.dockerignore 负责把
#    backend\.venv（29184 个文件）、frontend、backend\data 全部挡在门外
docker build -f deploy/Dockerfile -t kanban-backend:1.0 .

# 3) 把 nginx 也拉成本地镜像（一并打包带走）
docker pull --platform linux/amd64 nginx:1.27-alpine

# 4) 两个镜像导出成一个 tar —— 服务器只需 docker load，不用联网 pull
docker save kanban-backend:1.0 nginx:1.27-alpine -o kanban-images-1.0.tar

# 5) 组装部署包
$d = "kanban-deploy-$(Get-Date -Format yyyyMMdd)"
New-Item -ItemType Directory -Force "$d\nginx" | Out-Null
Copy-Item deploy\docker-compose.yml  $d\
Copy-Item deploy\deploy.sh           $d\
Copy-Item deploy\probe.sh            $d\
Copy-Item deploy\backup.sh           $d\
Copy-Item deploy\nginx\default.conf  "$d\nginx\"
Copy-Item frontend\dist -Recurse     $d\
Copy-Item backend\data  -Recurse     $d\
Copy-Item backend\config -Recurse    $d\
Move-Item kanban-images-1.0.tar      $d\
```

**生成口令文件**（Windows 上没有 `htpasswd` 命令，用 httpd 容器生成 bcrypt，跨平台通用）：

```powershell
docker run --rm httpd:alpine htpasswd -nbB kanban '你的口令' > "$d\nginx\.htpasswd"
Get-Content "$d\nginx\.htpasswd"     # 确认输出是 kanban:$2y$... 开头
```

> 若上一条因为重定向产生 UTF-16 BOM 导致 nginx 读不了，改用：
> `docker run --rm httpd:alpine htpasswd -nbB kanban '口令' | Out-File -Encoding ascii "$d\nginx\.htpasswd"`

**上传**（阿里云 ECS 公网**入方向流量免费**，1 GB 镜像随便传）：

```powershell
scp -r $d root@<服务器IP>:/opt/kanban
# 或者用宝塔/Xshell 的文件传输面板拖上去
```

### 打包时顺手确认三件事

```powershell
Get-Content "$d\nginx\.htpasswd"                     # 有内容、kanban:$2y$ 开头
Get-Item "$d\data\market.db" | Select Length          # ~1.6 MB，不是 0
# 连同我们自己的 conf 一起验一遍（缺 conf 的 nginx -t 等于没验）
docker run --rm `
  -v "${PWD}\$d\dist":/usr/share/nginx/html:ro `
  -v "${PWD}\$d\nginx\default.conf":/etc/nginx/conf.d/default.conf:ro `
  -v "${PWD}\$d\nginx\.htpasswd":/etc/nginx/.htpasswd:ro `
  nginx:1.27-alpine nginx -t
```

## 四、服务器端（4 步）

### 1. 装 Docker（Ubuntu/Debian，用阿里云源）

```bash
curl -fsSL https://get.docker.com | \
  sed -e 's|https://download.docker.com|https://mirrors.aliyun.com/docker-ce|g' | sh
docker compose version      # 应输出 v2.x，compose v2 插件随 docker-ce 一起装
```

> 我们是**离线部署**，不需要配 `registry-mirrors`；只有以后要在服务器上自己 `docker pull`
> 才需要，届时在 `/etc/docker/daemon.json` 里加当前可用的国内加速地址并 `systemctl restart docker`。

### 2. 一键部署

```bash
cd /opt/kanban
bash deploy.sh
```

它会依次：load 镜像 → `docker compose up -d` → 打印容器时区（**必须 `CST +0800`**）→ 自检
`GET /api/health` 不带口令是否返回 **401**。

### 3. 安全组

| 端口 | 说明 |
|---|---|
| 22 | SSH，最好限制成你自己的出口 IP |
| 80 | 看板（HTTPS 443 另配） |
| **8000** | ❌ **绝对不开** —— 后端只在 compose 内网里给 nginx 用 |
| 443 | 上 HTTPS 时再开 |

### 4. 验收（6 项，一项项打勾）

```bash
cd /opt/kanban
docker compose ps                     # 两个容器 Up、app 显示 healthy
docker compose exec app date          # 必须 CST +0800 ← 最关键的一项
docker compose logs app | grep 调度    # 应看到「盘后调度已按上次的设置保持关闭」
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/api/health   # 401 ✅
curl -s -u kanban:你的口令 http://127.0.0.1/api/health                 # 200 ✅
bash probe.sh                         # 出站连通性，详见第八节
```

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 容器时区 | `date` 输出 `CST +0800`，否则 16:30 会跑到北京时间 00:30 且交易日判断全错 |
| 2 | 定时任务 | 启动日志出现「盘后调度已按上次的设置保持关闭」= 你关的开关被继承了 |
| 3 | 鉴权 | 不带口令访问任何接口都是 **401**（这是 `app_secret` 的生死线） |
| 4 | 看板 | 浏览器开 `http://<IP>/` 弹口令框，进去后数据能出来 |
| 5 | 飞书入站 | 发「状态」，页面「已处理 N 条」+1 且有回复 —— 服务器出站 443 到 `open.feishu.cn` 通 |
| 6 | **数据源** | 先 `bash probe.sh` 全通，再飞书发一次 `轻跑`，看 `main_force.degraded` 与日志 —— 香港 IP 是否被东财风控，**这一项决定后面要不要做 Tushare 改造** |

## 五、定时任务怎么去掉、手动触发怎么用（零代码）

**你关掉的定时开关存在 `market.db` 的 `kv` 表里**（`scheduler_enabled = 0`，`scheduler.py:263`
启动时读它、尊重上次的设置），所以 **把 `data/` 打包带过去 = 定时任务自动保持关闭**，不用改任何代码。

三种手动触发（都走服务器抓取，配额、限速、回退链和本地完全一样）：

| 方式 | 操作 | 跑完推飞书摘要？ |
|---|---|---|
| 页面 | 「定时任务」页 → 执行一次 | ❌ 不推（`kind=manual`） |
| **飞书** | 给机器人发 `跑`（全量）/ `轻跑`（快速） | ✅ 推（`kind=feishu`），跑完连同摘要一起发你 |
| 兜底 CLI | `docker compose exec app python scripts/manage.py fetch` | ❌ 不推 |

> 兜底 CLI 是**另起一个进程**写同一个 SQLite：默认 journal 模式下可能报 `database is locked`
> （默认 5 秒超时）。前两条路都在后端进程内跑，没这个问题，优先用它们。

跑完想立刻看结果，飞书再发一条 `摘要` 即可。常用指令：`状态` `帮助` `候选` `板块` `摘要` `关注列表` `查询 600825`。

> 想重新开回定时：页面打开开关即可（写回 kv，容器重启也保留）。改时间则要动环境变量
> `STOCK_FETCH_HOUR` / `STOCK_FETCH_MINUTE`（见 `deploy/docker-compose.yml` 注释）。

## 六、以后怎么更新

| 场景 | 操作 |
|---|---|
| 只改前端 | 本地 `npm run build` → 覆盖服务器 `dist/` → `docker compose restart web` |
| 改评分模型 | 改服务器 `config/scorer.yaml` → `docker compose restart app` |
| 换飞书凭据/开关 | 直接在页面上改（写进 `data/market.db`），无需重启 |
| 改后端代码 | 本地 `docker build` → `docker save` → scp → `docker compose up -d --force-recreate` |
| 升级/回滚 | 用 `kanban-backend:1.1` 之类的新 tag，`docker compose up -d` 前改 `image:` 行；旧镜像 `docker save` 留一份 |

**备份**：见第十一节（`backup.sh` + crontab，走 SQLite Online Backup API，别直接 `cp`）。

## 七、服务器选型（已选定：香港节点）

| 项 | 选定 | 说明 |
|---|---|---|
| 地域 | **阿里云中国香港** | 免 ICP 备案 → **80/443 直接可用**，不用绕端口 |
| 规格 | **2 核 4 G（`ecs.e-c1m2.large`）优先**；只有 2 核 2 G（`ecs.e-c1m1.large`）也能跑，但建议加 2 G swap 兜底 | 系统+Docker 约 400 MB，Python(pandas/numpy/akshare) 常驻 300~600 MB；2 G 几乎无余量，抓取高峰有 OOM 风险 |
| 系统镜像 | **Ubuntu 24.04 LTS 64 位**（没有 22.04 也行） | 本文命令全是 `apt`；**别选阿里云 Linux / CentOS**（yum/dnf，第一节到十一节的命令要重写） |
| 架构 | **x86_64**（u1 / e 系列） | ⚠️ **避开倚天 ARM（u8y / g8y / c8y）** —— 本地 `docker save` 出来的是 `linux/amd64`，ARM 实例起不来，得换 `--platform` 重新构建 |
| 实例 | **经济型 e（共享型 x86）或通用型 u1**；避开 t5/t6 积分型 | e 系列**不限 CPU**（没有积分墙，不属于 t5/t6），但**无性能 SLA**（vCPU 会争抢物理核）。本项目是**网络 IO 密集**（限速 1.5~3.5s/请求），CPU 不是瓶颈 → e 够用 |
| 磁盘 | 40 GB ESSD | 镜像约 1 GB + SQLite 1.55 MB |
| 带宽 | **按使用流量，5 Mbps 峰值** | 看板页面+JSON 极小，按流量最划算；**入方向（你上传镜像）免费**。nginx 已开 gzip，首屏 JS 从 1.7 MB 压到 300~500 KB（5 Mbps ≈ 625 KB/s，不压要 2~3 秒） |
| 安全组 | 只开 **22 + 80 + 443**（+ ICMP 便于 ping 自检） | **8000 永不开** —— 后端只给 compose 内网里的 nginx |

> **如果最终只买到 2 核 2 G（`ecs.e-c1m1.large`）**，加 2 G swap 兜底，避免全量抓取高峰被 OOM 杀：
> ```bash
> sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && \
> sudo mkswap /swapfile && sudo swapon /swapfile
> echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
> free -h        # Swap: total 2.0Gi
> ```
> 换到 2 核 4 G（`ecs.e-c1m2.large`）就不需要这步。

**香港专属的四条注意：**

1. **时区照样要设**：香港也是 UTC+8，但 **Docker 容器默认是 UTC**，`TZ=Asia/Shanghai` 照设不误
   （Dockerfile 与 compose 都已写）。唯一判据：`docker compose exec app date` 必须是 `CST +0800`。
2. **国内镜像源在香港一般可达**：Dockerfile 的 pip 走了清华源、服务器装 Docker 换了阿里云 docker-ce
   源。若实测慢，删掉 `-i https://pypi.tuna...` 用官方 PyPI 即可。
3. **香港 IP 对东财的友好度未知**（可能比大陆机房 IP 更松，也可能更严）→ **部署后第一件事跑
   `probe.sh`**（见下节），再手动跑一次「轻跑」看结果 —— 这一项决定要不要推进数据源改造。
4. **延迟可忽略**：到东财/飞书 30~60 ms，你访问看板 <100 ms。

价格随活动浮动，以官网实时为准。

## 八、连通性预检（部署前后各跑一次）

```bash
cd /opt/kanban
bash probe.sh
```

只读探测 5 条真实出站路径（东财行情 / 历史 K 线 / 数据中心、腾讯行情、飞书 token），
**不写库、不触发抓取、不改任何东西**。

| 结果 | 判读 | 下一步 |
|---|---|---|
| 5 条全 ✅ | 出口干净 | 直接做验收第 6 项（手动跑一次「轻跑」） |
| 东财三条 ❌、腾讯 ✅ | IP 被东财限 / 域名被拦 | 先放开 compose 里 `STOCK_REQUEST_SENSITIVE_*` 放慢节奏；仍不行才谈数据源改造 |
| 飞书 ❌ | 入站遥控不可用 | 看板其余功能不受影响；查一下安全组出站有没有被改 |
| 全 ❌ | 容器根本没出网 | `docker compose logs app` 看 DNS / 网络 |

## 九、HTTPS（可选）

香港免备案，所以**有域名就能直接签真证书**；没域名也能跑，只是浏览器告警。

**方式 A：有域名（推荐）** —— 域名 A 记录指到香港 IP，80 端口可直接做校验：

```bash
sudo apt-get install -y certbot
docker compose stop web                        # standalone 模式要先让出 80
sudo certbot certonly --standalone -d kanban.你的域名.com \
     --agree-tos -m 你的邮箱@qq.com --no-eff-email
mkdir -p nginx/tls
sudo cp /etc/letsencrypt/live/kanban.你的域名.com/fullchain.pem nginx/tls/
sudo cp /etc/letsencrypt/live/kanban.你的域名.com/privkey.pem   nginx/tls/
docker compose up -d
```

**方式 B：没域名，自签**（浏览器会告警，但 basic_auth 照样生效）：

```bash
mkdir -p nginx/tls
docker run --rm -v "$PWD/nginx/tls":/t alpine/openssl req -x509 -nodes \
  -newkey rsa:2048 -days 825 -keyout /t/privkey.pem -out /t/fullchain.pem \
  -subj "/CN=kanban.local"
```

**两种方式共用的 nginx 片段**（`deploy/nginx/default.conf`）—— 80 改成跳转，443 里整段复制原内容：

```nginx
server {
    listen 80;
    server_name _;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name _;
    ssl_certificate     /etc/nginx/tls/fullchain.pem;
    ssl_certificate_key /etc/nginx/tls/privkey.pem;
    # ……把原 80 server 的内容整段复制进来（auth_basic / try_files / /api 反代）……
}
```

`docker-compose.yml` 相应加：

```yaml
    volumes:
      - ./nginx/tls:/etc/nginx/tls:ro
    ports:
      - "80:80"
      - "443:443"
```

改完自检：`docker compose config --quiet && docker compose up -d && docker compose exec web nginx -t`。

## 十、开机自启与故障恢复

| 场景 | 行为 |
|---|---|
| 服务器重启 | `systemctl is-enabled docker` 应为 `enabled`；不是就 `systemctl enable --now docker` |
| Docker 重启 / 容器崩溃 | `restart: unless-stopped` 自动拉起（两个服务都配了）；只有你**手动** `docker compose stop` 的不会自启 |
| 启动顺序 | `web` 有 `depends_on: [app]`，先起后端 |
| 飞书长连接 | 容器重启后 1~2 秒自愈（SDK 自带重连 + 60s 看门狗）；判据是日志**停止刷** `connect failed`、「已处理 N 条」继续增长 |
| 磁盘满 | 最常见的"莫名故障"：`df -h`、`docker system df`；日志已配 50m×5 轮转 |

## 十一、备份（`market.db` 才 1.55 MB，别偷懒）

```bash
bash backup.sh                 # 立刻出一份到 ./backup/
```

`crontab -e`（root）每天 03:10 自动跑、留 14 份：

```
10 3 * * * cd /opt/kanban && KEEP=14 bash backup.sh >> /opt/kanban/backup.log 2>&1
```

- 走 **SQLite Online Backup API**：默认 journal 模式下直接 `cp` 可能拿到写到一半的文件
- 一并备份 `trade_calendar.json`（路径写死在 `data/`）
- **恢复**：`docker compose down && cp backup/market-2026-09-30.db data/market.db && docker compose up -d`

## 十三、风险与已知限制（诚实清单）

0. **香港 IP 对东财的友好度还没验证**：这是本方案唯一的真未知数。部署后必须先 `bash probe.sh`，
   再手动跑一次「轻跑」；如果东财三条全挂而腾讯正常，再考虑放慢限速或推进数据源改造。

1. **东财对机房 IP 更狠**：家里 IP 是"节奏慢"，机房 IP 常被 push2 直接拒连/回空。板块资金流**没有**腾讯回退（只有行情/日线有），东财不通 = 板块时间轴半瘫。→ 这就是验收第 6 项要先测的原因，也是将来 Tushare 改造的落点。
2. **`/api/system/stop` 仍是雷**：靠 nginx 口令挡着，但口令输错点错就能停服（停了 `restart: unless-stopped` 会自己拉起来，不算灾难）。彻底关掉需要改代码（加个环境变量开关），**等你点头再做**。
3. **必须单 worker**：`Dockerfile` 的 `CMD` 不要加 `--workers` —— 会 SQLite 并发写冲突，且 16:30 的 cron 触发 N 次。
4. **日志改走 `docker logs`**：不再写 `run/backend.log`。已配 `50m x 5` 轮转，不会再无限涨。排障：`docker compose logs -f --since 30m app`。
5. **凭据安全**：`data/market.db` 含 `app_secret`。本机排查过程中它被打印到过一次终端/对话，介意的话去飞书后台重置 Secret 再到页面重填。
6. **`/docs`、`/openapi.json` 已在 nginx 关掉**（404），免得接口清单裸奔。
