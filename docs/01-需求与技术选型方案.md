# 股票市场可视化看板 — 需求与技术选型方案

> 版本 v0.1 · 2026-09-27 · 待确认
> 路线：**B — 参考开源项目结构自建** · 主力建仓：**自建打分模型**

---

## 1. 项目目标

做一个**盘后复盘看板**，每个交易日收盘后自动抓取数据，在本地网页一屏回答三个问题：

1. **钱去哪了** — 前一交易日各板块资金净流入/流出情况
2. **谁在极端波动** — 涨停、跌停、炸板股票全景，含连板梯队
3. **谁可能在偷偷建仓** — 用打分模型从全市场筛出疑似主力建仓的候选股

非交易系统，不产生买卖信号，仅供观察与研究。

## 4. 技术选型

### 4.1 选型对比

| 层 | 选定方案 | 备选 | 选择理由 |
|---|---|---|---|
| **数据源** | **AkShare** | Tushare（需 8000 积分才有涨停池） | 免费、无 token、涨停池/炸板池/跌停池/板块资金流接口齐全，文档 2026-09 仍在维护 |
| **后端** | **Python 3.12 + FastAPI** | Node.js（学 sector-flow 用原生） | 与 AkShare 同语言；vibe-astock 也是 FastAPI，方便对照抄 |
| **存储** | **SQLite** | Parquet / JSON 文件 | 单机盘后场景足够；无需部署数据库；支持历史回看查询 |
| **任务调度** | **APScheduler** | cron / Windows 计划任务 | 进程内调度，跨平台，便于做失败重试 |
| **前端** | **React 19 + TypeScript + Vite** | Vue 3 | 与 vibe-astock 同栈，抄组件不用翻译 |
| **图表** | **ECharts 5**（npm 本地依赖） | AntV / Plotly | 金融图表生态最全，K线/资金流/散点/热力图都有；学 sector-flow 不依赖 CDN |
| **UI 组件** | **Ant Design 5** | Element Plus | 表格能力最强（虚拟滚动、固定列、排序筛选），复盘表格是重头戏 |
| **状态** | Zustand | Redux | 轻量够用 |
| **运行** | 本地 `uvicorn` + `vite dev` | Docker | 先跑通本地，Docker 后补 |

### 4.2 为什么不用现成项目

- vibe-astock 的核心价值在 **AI 复盘**，要接 Codex/Claude 订阅或 API key；你只要看数据不要 AI 解读，等于背着 7 成不用的框架。
- **"疑似主力建仓"没有任何现成项目有**（因为没有标准定义），这块必须自己写，是本项目的核心差异化。
- 板块资金流和涨停池的数据源，大家用的都是同一套东财接口，抄和自建成本几乎一样。

## 8. 主力建仓打分模型（核心）

### 8.1 设计思路

"主力建仓"的可观测特征是：**资金在持续流入，但股价没有大涨**。所以模型围绕「钱进来了 + 价格没动 + 位置不高」三件事打分，再剔除情绪股（已经涨停连板的不是建仓是打板）。

### 8.2 粗筛（先缩小范围）

全市场约 5400 只，先剔除：

- ST / *ST
- 上市不足 60 个交易日的次新股
- 当日停牌
- 当日涨停、跌停（无法成交，且涨停股不是"建仓"场景）
- 流通市值 < 15 亿（易被小资金操纵，信号不可信）或 > 2000 亿（大盘股资金流信号钝化）

粗筛后约 2500–3500 只进入打分。

### 8.3 打分维度（满分 100，权重可在 `config/scorer.yaml` 调）

| # | 维度 | 指标定义 | 权重 | 数据 |
|---|---|---|---|---|
| 1 | **主力资金持续流入** | 近 5 日主力净流入总额 / 流通市值，且 ≥3 日为正 | **30** | 个股资金流 |
| 2 | **放量但不涨** | 近 5 日均量/20 日均量 ∈ [1.5, 4] **且** 近 5 日涨幅 ∈ [0%, 12%] | **20** | 日线 |
| 3 | **大单净额占比** | 近 5 日 (超大单+大单净流入)/成交额 均值 > 1% | **15** | 个股资金流 |
| 4 | **股价位置低** | 收盘价在近 250 日最高-最低区间的分位数 < 60% | **15** | 日线 |
| 5 | **换手适中** | 当日换手率 ∈ [3%, 12%]（有换手才有筹码交换，但不能是炒作） | **10** | 快照 |
| 6 | **筹码收敛** | 近 10 日振幅均值 < 前 20 日振幅均值 × 0.8（波动收窄=吸筹压价） | **10** | 日线 |

**负向剔除**：命中涨停池 / 连板数 ≥ 2 / 近 20 日涨幅 > 40% → 直接剔除，不参与打分。

### 8.4 计算方式

每个维度先做**分位数归一化**（在粗筛后的股票池里取百分位 0–100），再加权求和。这样避免不同量纲的指标互相淹没，也避免阈值设死。

```
score = Σ (percentile_rank(维度_i) × weight_i) / Σ weight_i
```

**实现后回填 —— 维度 2 会出现一档并列，这是正确行为**：

维度 2 是「且」条件，甜区函数在容差外会被钳到 0，因此**约 40% 的候选 `raw=0`**
（5 日均量 ≤ 前 20 日均量，即根本没放量；或 5 日跌幅超过 12%）。这批股票在
`rank(method="average")` 下会整体并列在**约 20 分位**，而非 0 分位 —— 并列块的
百分位等于块内平均名次，`114/289 → 第 57.5 名 → 19.9%`。

要点：

- 并列块整体位于所有非零值**之下**，百分位严格单调，不产生错序；
- 这批股票在该维度上确实不构成区分（都没放量），强行拉开差异等于编造信号；
- 改善幅度的验证方法：把零块占比从 50% 降到 40%、分位从 **46 降到 19.9**，
  就说明容差区间的部分计分生效了 —— 零块落在 46 会被误读成「中等」，
  落在 19.9 才是「明显偏低」。**若回归测试看到零块分位回到 40 以上，说明退化了。**

输出 **Top 30**，每只股票给出：

- 综合得分 + 六个维度的分项得分
- **命中原因文案**（规则生成，非 AI）：如「近5日主力净流入占流通市值 4.2%（5日中4日为正），量比 2.3 倍但涨幅仅 5.1%，股价处于近一年 38% 分位」
- 原始指标数值，供人工复核

### 8.5 必须做的验证（P2）

打分模型不验证就是自欺欺人。提供回测：取历史任意交易日的 Top 30，统计 T+5 / T+10 / T+20 平均收益与胜率，对比沪深 300 同期。**先跑出来看有没有超额，再决定信不信这个模型。**

**落地约束**（实现 M4 后回填，做 M7 前必读）：

- **可回测的最早日期 = `stock_net_inflow` 的最早日期。** 维度 1、3 依赖逐日落库的
  资金流序列，该序列从首次跑批（2026-09-24）才开始积累。早于此的日期跑不出
  维度 1、3，两维同时弃用后总权重从 100 掉到 **55**，分数与正常批次不可直接比。
- **粗筛输入也需要重建。** 快照字段（现价、涨跌幅、换手、成交额、流通市值）只有
  跑批当天的，回测历史日期必须先用日线回推这些字段 —— 这是 M7 的主要工作量，
  不是简单换个 `date` 参数。其中流通市值最麻烦：需要历史流通股本，
  目前只有深市能从交易所接口拿到，沪市靠 `成交额/换手率` 反推。
- **收益端**用 `stock_zh_a_hist` 向后取 T+N 日收盘价，基准沪深 300 用
  `stock_zh_index_daily`；样本内含新股与退市股，需统一按同一套负面过滤口径处理，
  否则幸存者偏差会把胜率抬高。

**因此更现实的路径是「滚动前瞻」而非「历史回测」**：每天盘后记下当日 Top 30
（快照已存），T+5/T+10/T+20 到期后回头补算收益。等积累够 60 个交易日再出结论。

### 8.6 免责

模型输出是"统计上长得像"，不是"主力真的在建仓"。资金流数据本身是按单笔大小推算的，存在误判，**不构成任何投资建议**。

## 11. 数据更新与容错

1. **定时**：APScheduler，交易日 16:30 触发（用交易日历判断，非交易日跳过）
2. **重试**：单接口失败重试 3 次，间隔 5s/15s/45s；整体失败的接口单独标记，不影响其他数据
3. **限速**：AkShare 请求间隔 0.5–1s，避免被上游封禁
4. **兜底**：实时接口失败 → 退回本地历史快照；仍无 → 加载 demo 数据，页面顶部明确标注"当前为演示数据"
5. **幂等**：按 `date` 主键 upsert，重复抓取不会产生脏数据
6. **可观测**：`/api/jobs/status` 返回最近一次成功抓取时间、各数据源状态

## 13. 风险提示

- **数据源风险**：AkShare 依赖公开网页接口，上游改版会导致接口失效。取数必须隔离在一层，便于快速修复。
- **资金流数据口径**：主力/大单是按单笔成交金额推算的，不是真实的机构账户数据，存在误判。
- **打分模型未经验证**：P0 版本的 Top 30 只是"统计特征命中"，有效性需 P2 回测确认。
- **免责声明**：本项目仅用于数据整理与可视化研究，不提供投资建议，不构成任何买卖依据。投资有风险，决策请自行判断。
